## 2. Current-state analysis

### Direct answer to Kuntai’s question

**Yes, with one caveat.**  
- For CB use case, the right L0 signal is already present in `lmcache_blend.l0_gpu_operation_duration_seconds` + `lmcache_blend.l0_gpu_transfer_{chunks,tokens}` from `CB_*_START/END` in `BlendMetricsSubscriber` (`lmcache/v1/mp_observability/subscribers/metrics/cb_server.py`).  
- `L0LifecycleSubscriber` (`.../l0_lifecycle.py`) is a different signal: vLLM physical block churn/reuse/eviction inferred from `MP_VLLM_BLOCK_ALLOCATION` + `MP_VLLM_END_SESSION`, not CB GPU copy duration.
- Caveat: `cb_store_pre_computed()` emits `CB_STORE_PRE_COMPUTED_START` before waiting on vLLM IPC event, unlike `cb_store_final()` which emits START after wait via `_cb_store_gpu_copy(start_event=...)`. That can skew “true GPU copy” timing semantics.
